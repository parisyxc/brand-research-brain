# v0.5.1 validation

Date: 2026-10-26, Asia/Seoul. Previous record: [v0.5.0](validation-v0.5.0.md). See [the diagnosis and learning acceptance](learning-quality.md).

## Scope and diagnosis

The two Doodle2Life reports had unequal research scope. The richer project report included additional comparison/community material; the plugin report also reflected a later growth question. This was not an isolated instruction A/B test. Nonetheless the plugin allowed abstract synthesis, repeated caveats and a growth refresh that changed the whole case's subject.

The patch adds a shared concrete-learning guide, bounded proactive comparison when a product-selection question warrants it, clear permission for labeled test examples, plain-language editorial checks and case-preserving growth updates. Both starter guides carry the learning purpose. No private project preferences, supplier conclusions or personal AGENTS.md are copied into defaults. The learning save schema is unchanged.

## Mechanical checks

74 helper tests pass: the existing 70 plus four tests for growth-only updates. They check stable case fields, required saved growth evidence, retained prior basis, repeated no-op, topic-drift rejection before writes and deliberate whole-case corrections. These tests validate file behavior, not readable reasoning.

Repository validation checks all three skill manifests/references, JSON/YAML, runtime syntax, compatibility metadata and release privacy boundaries. All four frozen offline replays pass; they remain historical mechanical checks rather than demonstrations of the new editorial behavior. Runtime remains Python 3.9+ standard library only; validation uses the existing development environment's PyYAML.

## Same-evidence editorial repair

The existing plugin Brain was copied to a private baseline and working candidate. Only its already-saved Doodle2Life case, linked notes and original raw records were used for the revision. No live retrieval or richer project-only competitor/community/supplier findings were added. The existing offer, three practices, category learning and two current-case hypotheses were rewritten as concrete buying choices and actions. The detailed growth investigation was retained; its snapshot counts/access/identity details did not become the HTML cover.

This is the primary agent's authored repair, not an independent fresh-agent execution. All 41 prior source records remained identical. All nine prior events and all raw files were preserved; one explicit learning-revision event was added. Other cases, the shared category's older UseIt content and the complete detailed Doodle2Life growth note were preserved. Checker errors were empty, with three brands, 41 sources and ten events. Repeated learning revision was duplicate and repeated HTML generation unchanged.

A temporary copy of the real candidate exercised a growth-only update: growth changed, cover/methods/category/ideas/action stayed identical, a repeat wrote nothing and an attempted cover replacement was rejected. This is separate from judging the quality of those sections.

The reviewed candidate was written back through the normal save helpers after checking that the original baseline had not changed. The old HTML is retained as a comparison archive; changed pages, state, digest and guide have a local backup. The Brain's existing profile/preferences remain unchanged. Its guide adopted only the new presentation/quality sections.

## Presentation and release checks

The actual revised HTML was opened in a browser. Desktop inspection checked the case-first cover and both reading/card modes; all six cards had no clipped content or horizontal overflow. A 390px iframe preview was visually inspected in both modes; this is not physical-phone testing. Print/PDF output was not generated or tested. The styling itself did not change in this patch.

Source and plugin archives are built and integrity checked, with required HTML assets and hidden compatibility files. Extracted source tests/validation and an isolated packaged-renderer smoke check are performed separately. The supported local install is verified as version 0.5.1, including component-byte parity and installed-helper behavior. This does not constitute a new-chat UI/behavior test.

## Limits

A source hash and a guard flag cannot guarantee specific, useful learning. The editorial comparison demonstrates a clearer same-evidence rewrite, not consistent behavior across every future brand or proof of the optional comparison workflow under live retrieval. A future new-chat trial remains useful for that question. No paid API, GitHub publication, social posting or brand launch is involved.
