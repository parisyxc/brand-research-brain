# v0.2.0 validation

Date: 2026-10-24, Asia/Seoul. [v0.1.1](validation-v0.1.1.md) and [v0.1.0](validation-v0.1.0.md) records remain available.

## Acceptance: learning rather than consulting

The active skills now aim for: supply an interesting site, understand the business, learn three concrete practices, and accumulate reusable knowledge for the learner's Shopify project. Six lenses guide internal attention; they do not impose six sections or fixed page counts. Business decisions, dimension tables and default consulting plans are absent from the new output workflow.

## Same-material author redesign

The author used six existing LiberNovo/competitor source records to write one concise case and one Shopify method in a blank Brain. This is an authored redesign and deterministic replay, not an independent forward test or fresh website research. All six raw records are byte-identical to the original test. The user's entire original test folder remains unchanged; a private full copy and checksum manifest are retained outside public packaging.

[Before/after comparison](libernovo-comparison.md) gives character counts and links. The public learning case covers business explanation, three observed practices, stage-appropriate application and one small next action. It avoids inferring profit, channel effectiveness, product performance or Shopify technology from page presentation.

## Independent forward evaluation

A separate agent received only the revised skills, six saved raw records and a realistic Chinese request from an early-stage Shopify learner. It did not read the author example or old wiki synthesis and did not browse the web. In a blank Brain it produced **1 case, 2 reusable Shopify notes, 6 sources, 1 event**. All 33 wikilinks resolved; checker errors were empty. Repeating initialization, intake and an identical explicit revision left all 15 Brain files unchanged; input files were unchanged.

Actual practices were: explain features through actions/product parts, make version boundaries explicit, and accompany trial promises with their conditions. The next action was a small product-page sketch for the learner. No category decision, consulting roadmap, growth attribution or SEO claim was invented. Actual outputs and a portable review are in [examples/forward-v0.2](../examples/forward-v0.2/evaluation.json).

Minor readability issues were long repeated source names and repeated caveats. A narrow skill wording refinement now recommends short inline references with a raw-source footer and a shared limitations statement. The preserved forward output predates that editorial refinement; it was not silently rewritten.

## Scope and limits

This release validates local helper behavior and skill behavior with saved website material. It does not claim fresh live-site coverage, a new installed-host UI/discovery test, an Obsidian UI test, a Claude integration test, GitHub publication or public-directory submission. Source/ZIP updates do not replace an installed v0.1.1 cache.

Research truth and usefulness require reading the content; the checker validates file relationships. Exact record deduplication is not semantic deduplication. Writes are atomic per file, not a crash-proof multi-file transaction. Plugin updates preserve existing Brain files rather than silently migrating them.
