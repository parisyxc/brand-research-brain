# v0.6.0 validation

Date: 2026-10-26, Asia/Seoul. Previous record: [v0.5.2](validation-v0.5.2.md).

## Change

Detailed growth studies can now remain inside the HTML reading document rather than being compressed into three overview points. The optional additive `growth.details` field supports visible chapters, per-item lessons, internal navigation and separate panels in card mode. Source references allow up to 40 entries. Concise inputs remain valid; six main document sections and growth-only protection are preserved. No learning/registry schema migration is introduced.

Growth instructions and presentation guidance now distinguish a concise first pass from a completed or explicitly detailed study. Presentation-only requests reuse saved research without retrieval, provider calls, credential access or new research events. The product does not bundle a Monid connector.

## Mechanical checks

78 tests pass: the previous 74 plus four cases covering visible detailed growth/lessons with case preservation and no-op, nested untrusted-text escaping, invalid detail shapes before writes, and more than 20 references. These checks validate mechanics rather than learning quality. Repository validation checks the three skills, references, metadata parity, syntax, YAML/JSON and release boundaries. All four historical offline replays remain passing mechanical regressions.

## CharCharms presentation example

The completed user growth note was read in full. Only declared Markdown, the current digest/HTML and the guide were staged, rather than copying a vault or provider configuration. Public source metadata was resolved from raw records named by the note; credential contents were not accessed. No live research or provider call occurred.

A private coverage map connects the existing note's substantive sections to six chapters: evidenced growth phases; concrete content practices; creator/retail/SEO paths; metric interpretation; learner application; further reading. Historical claims, disclosed sponsorship, observed media and proposed adaptations remain distinguishable. Data dates, sample boundaries, long-tail distribution and missing order attribution are retained. Research mechanics remain primarily in the final source annotation.

Core case fields and the other four case sections are unchanged. The current Markdown, raw records, profile and research registry/log remain intact. The reviewed HTML and digest were written back with growth-only protection; the earlier overview-only HTML is archived and changed presentation/guide files backed up. A repeat is unchanged, with no new research event. This is primary-agent editorial coverage review, not an independent fresh-agent behavior evaluation or independent verification of the supplied research.

## Browser and release checks

The actual document was inspected at 1280px width in continuous reading and card modes. The six growth topics and overview had no horizontal overflow or clipped content; local chapter anchors resolve. Native controls retain the selected chapter when switching reading/card modes. A 390px iframe preview was visually inspected; this is narrow-layout inspection rather than physical-device testing. Print styles were added, but a final PDF/print was not tested.

Source and plugin archives are built, integrity checked and compared with source components. Extracted source tests/validation and isolated packaged-renderer smoke checks are performed separately. Supported local installation is verified at version 0.6.0 with component-byte parity and installed helper behavior. New-chat UI behavior and consistency across other brands are not claimed as tested. Private examples, backups, provider files and credentials are excluded from release.

No paid API call, GitHub publication, social posting or business execution is performed.
