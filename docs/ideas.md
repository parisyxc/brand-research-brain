# Ideas：先理解当前案例，再判断如何积累

每次 intake 仍检查四类知识；ideas 的第一步是从当前案例自身提炼启发和待验证假设。

先问：这个案例让我们看到什么用户任务、摩擦、机制或取舍？由此产生了什么值得验证的问题？区分来源中的观察、自己的解释与未知项。

再决定放在哪里：

- 与已有想法研究同一个用户问题或机制，并新增了实质假设/验证问题：合并更新，保留旧范围与证据。
- 当前案例提出不同的问题，而且材料足以形成有用假设：单独建页，链接当前案例与来源。
- 材料不足、只剩通用建议，或无法形成值得验证的问题：保留或暂不建页，不为了文件数量生造业务。

例如，UseIt 的赠礼和定制场景可以支持场景卡片想法；Looki 的低操作负担记录与回顾，则应先问“用户缺的是拍摄，还是已有素材的整理和回看”。后者可以产生独立假设，不应只变成给旧卡片增加一组 FAQ。是否提出新服务、选哪个受众，仍需证据与用户选择；宠物、穿戴设备或某种数字产品都不是插件默认方向。

“把某个页面方法用在旧商品上”可以是跨案例应用，但不能代替当前案例自身的启发。反过来，也不要求每个品牌固定生成一份独立产品想法；有清楚的共同问题时合并更合适。

后台 ideas 理由记录来源观察、假设及页面选择原因。它不进入案例、日志或聊天检查表，也不增加保存格式字段。最后只展示有用的学习和实际更新。

仓库 `examples/reconciliation` 保留的是 v0.4.0 的机械沉淀示例：当时将 Looki 应用追加到了旧卡片。它仍用于回归测试保存、保留和去重，不作为本规则的行为验收答案。新版判断通过独立 agent 的真实执行另行验证。
