# Shopify 学习指南

这个 Brain 用来从感兴趣的网站学习：读懂生意，发现选品切口，学习建站、内容与增长，服务自己的 Shopify 实践。`brain.json` 保存目标、阶段、语言与兴趣。市场、预算和供应偏好未知时留空，已有偏好优先。

采用 Karpathy 的 LLM Wiki 模式：`raw/` 保存不可覆盖的来源，`wiki/` 保存持续更新、彼此关联的知识，本指南与 `AGENTS.md` 提供操作上下文。把本文件夹作为 Obsidian vault 打开即可；Claude 或 Codex 都可维护这些 Markdown 文件。

一次网站研究是一次学习：贡献证据的网页分别保存 raw 记录，合成一篇易读案例，提炼三个具体做法，给自己一个小行动。内部考虑选品与洞察、产品与品牌、建站与转化、内容、获客增长、SEO；只展开有证据的部分。材料不足时少写几个做法，不编造内容凑数。

- `wiki/brands/`：生意解释与简洁的案例学习。
- `wiki/categories/`：品类、用户问题与选品学习。
- `wiki/shopify/`：建站、产品页与转化方法。
- `wiki/growth/`：内容、获客、SEO 与留存方法。
- `wiki/ideas/`：与自己项目相关的想法。
- `wiki/index.md`、`wiki/log.md`：易读导航与简短学习记录。
- `raw/sources/`、`raw/assets/`、`raw/build-log/`：来源、附件和真实实践记录。
- `.brb/`：来源指纹与处理状态，技术细节留在这里。

有可复用价值时新增或合并主题笔记，链接案例与来源，保留已有结论和用户修正；不为填满目录建页。后续提问应利用这些关联知识，在合适时跨案例比较。

区分页面观察、品牌自述与自己的理解。用来源名和章节引用；官网展示不能证明效果、需求、营收或因果，也不默认对方使用 Shopify。默认不评分、不判断 Study/Kill、不展示维度检查表、不生成咨询路线图。用户明确需要时再深入策略。

原始材料不覆盖，知识页先读后改，无关文件保持不变。新学习用 plugin 的 `learn.py` 合并写入并只记一条简短日志；相同材料重复学习默认无变更，重新解释则显式修订。旧记录保留可读。本地研究不自动授权联系他人、采购或发布。

## 后台知识沉淀检查

每次 intake 或深入 growth 研究都读取并检查 categories、ideas、shopify、growth。有实质新增就合并或建页，相关旧页无新增则保留，材料不足则暂不建页。四项处理及理由通过 `knowledge_reviews` 只存入 `.brb/state.json`；不在案例、索引、日志或聊天中展示检查表。保持单页简洁，同时完成知识关联。已有想法可以新增待验证借鉴，但不把建议写成已完成行动。

Ideas 先从当前案例的用户任务、摩擦或机制提炼独立启发和待验证假设，再判断是否适合旧想法。只有用户问题或机制相同、且有实质新假设/验证问题时才合并；否则有内容就独立建页，材料不足则保留或暂不建页。不把新案例强行套进旧项目，也不要求每个品牌都生造一个产品想法。跨案例应用不能代替当前案例自身的想法沉淀。

## HTML 学习文档

每次案例 intake 或深入 growth 后，额外生成或刷新 `reports/<品牌>.html`：用精简中文整合事实、具体方法、品类洞察、增长洞察和当前案例的灵感，来源放在末尾。支持连续阅读、分页知识卡和浏览器打印；也可明确要求本次只保留 Markdown。HTML 依据已保存笔记提炼，Markdown 仍是知识库；后台依据放在 `.brb/share/`，不增加研究事件。已有文档先读后更新，未知的渠道和效果保留为未知，不因展示需要编造内容。

## 让学习具体、易读

先讲清谁在什么时刻买什么、用什么替代、为什么这个做法值得学，再给可尝试的小步骤。品类与 ideas 用具体场景和选择解释，不只写“参与感”“机制”“交付边界”等概念。可以提出明确标为假设的例子，不能把它写成已验证需求或已选方向。重要选品问题可做一次有边界的补查，不把短笔记误解成只能停在表面。共同的证据限制在末尾说明一次，改变判断的限定仍保留在相应句子。

补充 growth 时保留案例主线、原有方法和独立 ideas，只把新渠道学习合并到增长部分；没有证实增长不妨碍从真实页面提炼可测试的表达。不要让账号计数、访问受限或“尚未证实”成为整个案例的主题。

## 品类先讲本案，再谈借鉴

品类部分先说明当前品牌属于什么品类、具体卖哪些产品，再解释它改变了原来哪一种产品角色或购买理由、亮点有什么实物或页面依据，最后才谈可借鉴原则。不能直接用用户将来想做的产品替代本案品类，也不能一开始只列使用负担和实现难点。品类创新不等于首创或销量成因；用户方向、候选技术与测试主要放在明确标注的借鉴或 ideas 部分。此顺序适用于案例、品类笔记和 HTML，不增加页面数量要求。

## 完整增长研究的 HTML 呈现

已有深入增长笔记时，HTML 先保留简短概览，再在同一文档展开有依据的增长阶段、内容实例、社交/创作者/SEO与零售路径、数据解读和借鉴。专题默认全部可读，知识卡模式按专题分卡；不因三条要点的格式丢掉研究内容，也不要求回到 Markdown 才能读完整学习。普通 intake 仍简洁，不为填满章节生造阶段。只更新展示时复用已有研究，不重跑 API、不读取凭据、不新增研究日志；原案例、品类与 ideas 继续保留。
