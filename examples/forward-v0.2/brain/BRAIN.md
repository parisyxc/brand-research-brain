# Shopify 学习指南

这个 Brain 用来从感兴趣的网站学习：读懂生意，发现选品切口，学习建站、内容与增长，服务自己的 Shopify 实践。`brain.json` 保存目标、阶段、语言与兴趣。市场、预算和供应偏好未知时留空，已有偏好优先。

采用 Karpathy 的 LLM Wiki 模式：`raw/` 保存不可覆盖的来源，`wiki/` 保存持续更新、彼此关联的知识，本指南与 `AGENTS.md` 提供操作上下文。把本文件夹作为 Obsidian vault 打开即可；Claude 或 Codex 都可维护这些 Markdown 文件。

一次网站研究是一次学习：贡献证据的网页分别保存 raw 记录，合成一篇易读案例，提炼三个具体做法，给自己一个小行动。内部考虑选品与洞察、产品与品牌、建站与转化、内容、获客增长、SEO；只展开有证据的部分。材料不足时少写几个做法，不编造内容凑数。

- `wiki/brands/`：生意解释与简洁的案例学习。
- `wiki/categories/`：品类、用户问题与选品学习。
- `wiki/shopify/`：建站、产品页与转化方法。
- `wiki/growth/`：内容、获客、SEO 与留存方法。
- `wiki/ideas/`：与自己项目相关的想法。
- `wiki/index.md`、`wiki/log.md`：易读导航与简短学习记录。
- `raw/sources/`、`raw/assets/`、`raw/build-log/`：来源、附件和真实实践记录。
- `.brb/`：来源指纹与处理状态，技术细节留在这里。

有可复用价值时新增或合并主题笔记，链接案例与来源，保留已有结论和用户修正；不为填满目录建页。后续提问应利用这些关联知识，在合适时跨案例比较。

区分页面观察、品牌自述与自己的理解。用来源名和章节引用；官网展示不能证明效果、需求、营收或因果，也不默认对方使用 Shopify。默认不评分、不判断 Study/Kill、不展示维度检查表、不生成咨询路线图。用户明确需要时再深入策略。

原始材料不覆盖，知识页先读后改，无关文件保持不变。新学习用 plugin 的 `learn.py` 合并写入并只记一条简短日志；相同材料重复学习默认无变更，重新解释则显式修订。旧记录保留可读。本地研究不自动授权联系他人、采购或发布。
